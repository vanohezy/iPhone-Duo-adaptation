# 验证与效果验收

测试对象是用户任务的连续体验。下面为本技能建议的验证方法；不代表 Apple 的认证流程，也不保证仅靠这些检查就发现所有问题。

## 建立可复查的记录

记录实际 App 版本/构建、构建 SDK、部署版本、OS、设备或模拟器、页面/业务对象、初始数据和可重复步骤。给截图/短录屏路径，标注“观察”“静态推断”“未验证”。

使用 Xcode [Device Hub](https://developer.apple.com/documentation/xcode/device-hub) 的 Duo 控件测试关闭、打开、旋转、折叠及系统分屏。依据当前工具文档操作，不编造模拟器命令或用普通 iPhone 截图伪装 Duo。

## 覆盖方式

不要机械执行所有设置的笛卡尔积。每条核心任务先遍历主要状态；针对高风险组件补组合。外屏、展开内屏两个方向、书本半折、桌面半折、左右分屏、剩余高度减少都应有证据或明确限制。

| 场景 | 应完成的真实动作 | 通过条件 |
| --- | --- | --- |
| 外屏核心流程 | 查找对象、打开详情、执行主要动作、返回 | 功能完整、侧栏不遮挡、返回路径可预测 |
| 内屏充分展开 | 快速切换对象并保持详情上下文 | 增加上下文/视野；没有简单拉伸或压缩成过窄多栏 |
| 内屏纵向 | 阅读、编辑和提交同一内容 | 栏和内容重排合理；操作与层级不改变 |
| 书本半折 | 点按靠近中心的项目、菜单、卡片 | 关键触点避开保留区；能阅读全部内容 |
| 桌面半折 | 播放/阅读并操作下方控制；需要时输入 | 视线与操作区明确；功能不减少；曲面不截断关键 UI |
| 左右系统分屏 | 分别放在两边完成核心流程 | 每边 inset 正确；依当前窗口布局；不把另一 App 当内部详情 |
| PiP/剩余高度减少 | 在媒体占顶端空间时继续 App 核心任务 | 可滚动到关键内容；toolbar overflow 有序且动作可达 |
| 键盘与输入法 | 写长草稿，移动光标，展开/收回，再提交 | 草稿/选区/焦点保持；字段和提交入口没有被遮挡 |
| 相机与弹层 | 打开相机、启停，显示菜单/sheet/alert | 动态 reserved region 被正确处理；弹层不落在折叠曲面 |

## 连续性回归：按业务状态断言

把容易丢失的状态写成可核对的值，在转换前后比对。模拟器截图只能证明静态视觉，连续过程优先用录屏和操作记录。

1. **浏览**：外屏打开非首项，滚动到中段；展开、半折、合拢，再返回列表。仍是同一对象，语义位置和选中项可辨认。
2. **编辑**：输入未保存草稿，改变光标/选区；多次改变空间，最后保存一次。草稿无丢字、无重复提交，撤销历史按产品约定保留。
3. **导航**：在每个顶级分区进入不同层级；展开收回、切换 tab。各路径独立且可返回，没有突然多一层或跳到首页。
4. **媒体**：播放中记录时间、音轨、字幕、队列；开合与进入/退出分屏。播放时间按经过的时长连续前进，暂停时保持原位置；不能以进度数值相等作为播放中连续性的断言。没有重播、双重声音或意外暂停。
5. **异步任务**：上传、搜索或长请求进行中切布局。任务不会被无故重复或取消；结果归属同一业务对象。
6. **多场景**：同一 App 两窗口看不同对象；一边编辑，另一边刷新/切换。共享数据一致，UI 选择不互相覆盖，创建不可用时能正确响应。
7. **画布/游戏**：记录世界坐标、缩放、选区/分数/棋盘；改变渲染尺寸后点按已知位置。状态不变，命中位置和渲染一致。
8. **中断恢复**：在折叠与键盘/相机状态变化附近进入后台再返回。没有多次启动会话或丢失待完成操作。

先执行正常开合，再重复往返几次检查边界抖动和资源副作用。发现错误后用最小步骤复现；不要把固定循环次数冒充平台要求。

## 视觉、交互与无障碍交叉项

- 最大系统辅助文字尺寸与至少一种长文本语言；有目标市场时加入 RTL。大字能降列、增高和滚动，而不是缩字号。
- VoiceOver 顺序与当前焦点：布局改变后仍能理解所在对象，隐藏栏不重复朗读，symbol 有名称，overflow 中动作仍可达。
- 标准与自绘主要控件采用舒适触点，通常以 44×44 pt 作为设计目标；不要把图标视觉尺寸当触点尺寸。侧边相邻操作需要足够间隔。
- 浅色、深色、Increase Contrast、Reduce Motion；素材裁剪和对比度用实际值验证，不从压缩截图猜精确数值。
- 弹层、搜索结果、空态、错误、加载、长标题、系统 Live Activity 扩大时的栏压缩，优先测本次改动触及的组件。
- 外接键盘/指针仅在产品支持或任务相关时加入；检查快捷键、焦点、选区和返回路径。

依据：Apple [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)。这些辅助功能目标在所有空间状态中成立。

## 性能与生命周期

静态检查或日志怀疑重建时，观察 model/player/session/engine 创建次数、重复请求和提交次数。需要时用项目已有日志或 Instruments 定位；不要为了适配引入永久高频采样与大量日志。

对几何回调、媒体重新解码、整页渲染和大列表重排分别观察。性能验收使用项目已有预算；报告设备和测量条件，不随意宣称固定帧率是所有 App 的通过标准。

## 分层结论

| 证据层 | 可以说明 | 仍不能说明 |
| --- | --- | --- |
| 静态审查/扫描 | 发现已确认代码问题与候选风险 | 实际布局和状态转换已正确 |
| 构建/测试构建 | 此 SDK/目标可编译与链接 | 模拟器或真机已运行 |
| 模拟器交互 | 所测状态下的视觉与任务行为 | 真机触达、设备稳定性、物理铰链、真实媒体/相机性能 |
| 物理设备安装 | 指定构建已安装到确认设备 | 已启动或完成验收 |
| 真机任务验收 | 所测任务与姿态的观察结果 | 所有姿态、语言、辅助功能及后续版本都无问题 |

## 交付记录格式

按实际工作填写，不保留空模板作为最终结果：

| 任务 / 状态 | 优化前问题 | 当前效果 | 证据路径与层级 | 结论 |
| --- | --- | --- | --- | --- |
| 具体页面和动作 | 可复现现象 | 当前观察或设计目标 | 文件/截图/录屏/日志 | 通过 / 失败 / 未测 / 不适用与原因 |

没有源代码、构建工具、可运行目标或真实设备时完成其余工作，准确列出相应缺口。安装遵循用户和项目既有约定，保持签名和数据；不要为了验证直接卸载旧 App。
