# 各状态布局与效果契约

这是将官方能力用于项目的设计方法。表中的效果是建议和验收目标，不是 Apple 对每个 App 的固定模板。平台事实见 [official-guidance.md](official-guidance.md)，案例见 [app-patterns.md](app-patterns.md)。

## 先决定如何利用更多空间

| 任务结构 | compact | regular / 空间充足 | 选择条件 |
| --- | --- | --- | --- |
| 列表 → 详情 | 一个导航栈显示当前层级 | 列表与当前详情并列 | 用户需要频繁切换对象；保持选择与返回语义 |
| 内容 + 辅助细节 | 内容优先，细节可进入 | split arrangement 同时呈现 | 两部分都不能被遮挡，例如播放与逐字稿 |
| 内容 + 浮动控制 | 可恢复的覆盖控制 | overlay arrangement；折叠时分配可用区域 | 前景/背景关系明确，滚动后内容可完整访问 |
| 复杂顶级分类 | tabs + 各自导航路径 | 需要时改为 sidebar | 分类和层级复杂才用；不要为展开机械增加一列 |
| 单一阅读/表单 | 舒适单列 | 限制文字行宽，按任务增加辅助信息或留白 | 宽屏不意味着所有文字都必须占满 |
| 图库/商品/信息卡 | 按最小可读卡片尺寸排布 | 增加列数，图片不变形 | 同时检查大字、内容长短和半折分布 |
| 画布/地图/棋盘 | 操作不压住主体 | 扩展视野或独立工具区 | 保持坐标、缩放、当前选择和命中映射 |

`NavigationSplitView` 用于信息层级；`ArrangementView` 用于两个内容区域的布局。两者不是互换名称。模式可组合，但由外层导航持有任务上下文。

## 各状态目标

记录每个状态的实际容器尺寸、两个 size class、四边 safe area、reserved regions；不要把姿态名称直接当布局输入。

| 状态/情境 | 期望效果 | 重点核查 |
| --- | --- | --- |
| 合拢使用外屏 | 单个核心任务清晰，侧边导航/操作为内容保留高度 | 文字未被侧栏裁掉；返回、新建、提交可触达；相机/动态岛避让 |
| 内屏充分展开，较宽布局 | 增加有意义的上下文，列表与详情或内容与辅助区同时可见 | 当前对象不变；主内容没被无价值侧栏挤小；媒体焦点保留 |
| 内屏纵向 | 根据实际空间改成上下或舒适单列；接受系统水平栏 | 不机械保留双窄栏；正文行宽合理；按钮不因栏方向改变而丢失 |
| 书本式半折 | 左右内容围绕可用区域稳定排列，关键操作避开曲面 | 卡片、按钮、正文关键段不被不舒适区域切断；不随角度频繁换布局 |
| 桌面式半折 | 适合产品时上部展示、下部操作；同一套功能和层级 | 点击不使设备失稳；播放、创作等核心操作靠近操控区；键盘出现后仍可完成任务 |
| 外屏朝外的支撑/帐篷使用 | 延续外屏的合理布局；支持的方向仍可完整使用 | 不假定内屏激活，不用自己推算角度；相机/时钟/媒体等按任务处理 |
| 打开/合拢的中间过程 | 布局随系统几何变化，保持正在做的事 | 不闪回首页、重新加载、重复提交、跳到列表首项或重启播放 |
| 系统分屏，App 在左侧 | 根据本窗口重新降级为适合的布局 | 系统控件可能在左；检查每边安全区，不硬编码“右侧留白” |
| 系统分屏，App 在右侧 | 与左侧功能和状态一致，操作在系统安排的边缘 | 不用整个屏幕的宽度决定显示两栏；场景状态正确隔离 |
| PiP 钉在上方/窗口高度被压缩 | 按剩余高度保住核心内容与操作 | 工具栏压缩有序；正文可滚动；不能只适配“宽度变小” |
| 键盘/输入法候选栏出现 | 当前字段与提交/取消入口可访问 | 不重复扣键盘高度；草稿、光标/选区保留，折叠不无故收键盘 |
| 相机启用/停用 | 对新增/消失的相机 reserved region 作正确响应 | 自绘 HUD 不被遮挡；会话不因 UI 布局重排中断 |

物理设备能否进入某个姿态、方向或附件状态由系统/SDK与真实能力决定。无法进入就记录限制，不制造截图作为通过证据。

## 关键细节的优化判据

**视觉重心。** 有侧栏时先按内容安全区对齐。沉浸式背景可覆盖全屏；任何前景交互都要独立检查。不要给所有元素统一加一个右边距。

**层级。** 展开增加“同时可见”的内容，而不是改变对象的归属、分类或动作名称。收回时显示用户正在操作的详情；回到列表时仍能辨认选中项。

**网格。** 半折时可优先让网格在两侧均衡分配；偶数列只在卡片仍可读、可点时有益。大字需要减少列数时不要牺牲可访问性来凑偶数。

**媒体。** 根据内容而非外框决定 fit/fill。人物、字幕、棋盘、图表轴等有意义区域不能被裁掉；允许背景填充，不拉伸主体。持续播放、音轨、字幕和时间位置要保持。

**工具栏。** 为当前任务排序：返回/关闭和提交等关键操作清楚，常用动作优先留在栏内，其余进入可发现的 overflow。列表操作留在列表附近，详情操作保持与详情关系明确。

**折叠避让。** 系统容器先处理。静态、需要精确点击的元素优先避开 reserved region；可滚动内容不必全部切成两块，只需确保最终完整可读可操作。

**动效。** 折叠本身已是强变化。避免同时飞入多组控件、重复转场和因边界抖动反复切换；Reduce Motion 下以稳定重排或轻量过渡保证可理解。

## 按产品选择优化

- **效率/邮件/聊天**：列表与当前内容并列；搜索词、会话草稿、未读锚点、发送状态不变。新消息/任务快捷入口在外屏同样可用。
- **阅读/笔记**：文本位置按段落/对象 ID 保持；阅读宽度受控。允许宽屏辅助目录，避免未经验证的双页分页导致阅读顺序跳跃。
- **媒体**：播放器与逐字稿/队列有明确关系；桌面姿态适合上下分配，但字幕和控制不能被曲面截断。
- **创作/扫描/相机**：画布、预览、工具、检查器按任务组合。纸张边缘/裁剪手柄/快门避让；保留缩放、选区、撤销栈和正在录制的资源。
- **游戏**：以局面与可操作区域决定缩放；画面渲染尺寸和触控坐标同步更新，HUD 依据安全区。大屏增加视野或舒适操作空间，未经产品决策不改变规则和难度。
- **轻表单/设置**：一列即可时保留一列，控制行宽；展开后可增加说明，不能用无关推荐填空白。

## 最小页面契约示例（本技能设计建议）

| 页面 | compact | regular | 半折/高度不足 | 不变量 |
| --- | --- | --- | --- | --- |
| 项目详情 | 当前任务详情，返回项目列表 | 项目列表 + 当前任务 | 系统容器避让，辅助说明进入可恢复入口 | taskID、草稿、导航路径、滚动锚点、保存操作不变 |
| 播放页 | 封面/播放与逐字稿切换 | 播放 + 逐字稿 | arrangement 调整方向；保留字幕、进度与队列入口 | player 实例、音轨和播放状态保留，播放时间连续前进 |

实际项目替换这些示例，给出优化前后的任务证据。不要把这张示例表当成已经完成的设计。
