# 优秀 App 案例与可迁移模式

核实日期：2026-11-02。以下 7 个主案例均有 App 厂商或 Apple 的原始公开资料。证据层级是“官方描述 / 已发布版本说明”，本次没有在本机或用户真机上安装、操作这些 App。不要写成亲测结论，也不要把某个姿态的宣传图扩张为全状态验收通过。

**读法**：“已证实”只归纳来源明确写出的行为；“迁移判断、边界、验证”是本 skill 的设计和工程推导，不是原厂实现声明。选用与当前任务相符的 2–3 例深入对照即可，不要求把每种模式都塞进一个 App。

## 1. Things：展开导航，保留专注与直接操作

**已证实（Duo 已发布）**：Cultured Code 于 2026-10-23 发布 Things 3.25。展开显示侧栏，用户可隐藏；转到竖屏会自动隐藏侧栏。支持两个 Things 窗口并排，并在列表间拖放待办；外接键盘提供完整快捷键和持续选择。工具放到侧边，列表保持纸张般的留白。[厂商原文与配图：Hello Duo](https://culturedcode.com/things/blog/2026/10/hello-duo/)

**迁移判断**：把额外空间用于缩短“换列表 → 找项目 → 操作”的路径，同时保留一键回到专注内容的出口。双窗口服务于比较与搬运，不能与单窗口内的侧栏混为一谈。

- **适用**：待办、文件、收藏、笔记等用户经常跨容器整理内容的产品。
- **边界 / 反模式**：侧栏不是展开状态的永久装饰。长文、输入或窄 Split View 中，强留侧栏会挤压核心任务；不要照抄外观而遗失拖放、选择、撤销等完整交互。
- **如何验证**：选中一个项目并滚动到中部，在展开、旋转、隐藏侧栏、收拢之间往返；仍是同一列表和项目。若启用双窗口，分别保留导航与选择，拖动只产生一次数据变更，另一窗口及时反映；用键盘确认焦点不会掉回根节点。

## 2. Fantastical：上下文可见，但让主内容赢得空间

**已证实（Duo 已发布）**：Flexibits 于 2026-10-23 描述合拢时为常规 iPhone 布局、展开时采用较大的 iPad 式布局；可隐藏侧栏以放大周/月视图，可打开两个窗口比较不同周。[厂商 Duo 介绍](https://flexibits.com/blog/2026/10/twice-as-nice-fantastical-cardhop-go-iphone-duo/)；[版本记录：4.2.3 / 4.2.4 包含 Duo 支持](https://flexibits.com/fantastical-ios/releasenotes)

**迁移判断**：优先增加与当前决策相关的信息，例如“本周整体冲突 + 正在编辑的事件”；信息密度由任务决定，不应只增加空白网格或机械增加列数。该厂商称其为 iPad 式布局，不代表所有 iPad 布局都适合直接复制到 Duo。

- **适用**：日历、排期、库存、数据比较，以及需要同时看概览和细节的界面。
- **边界 / 反模式**：把所有筛选、日历源和详情永远铺开，会挤没时间网格。辅助栏收起后应保留明确入口和当前筛选提示。
- **如何验证**：在选定日期、筛选和滚动时间段下改变窗口尺寸，保持该上下文。编辑事件时打开键盘，检查起止时间和保存入口；双窗口改变日期不能无意改动另一窗口的浏览位置。

## 3. Cardhop：输入与结果同时可见

**已证实（Duo 已发布）**：同一 Flexibits 发布介绍明确说明：展开时左侧联系人列表、右侧完整资料；创建联系人时可在左侧输入解析内容，右侧实时形成联系人卡片。[厂商 Duo 介绍](https://flexibits.com/blog/2026/10/twice-as-nice-fantastical-cardhop-go-iphone-duo/)；[版本记录：2.5.1，2026-10-20](https://flexibits.com/cardhop-ios/releasenotes)

**迁移判断**：比单纯的 list-detail 更进一步，用两区呈现“输入 / 控制 → 即时结果”，降低用户在编辑页和预览页间切换的成本。两区共享同一草稿模型，但导航和聚焦属于各自视图状态。

- **适用**：表单、自然语言录入、搜索筛选、规则构建、账单编辑、创作预览。
- **边界 / 反模式**：没有足够结果内容时不要强开空预览；输入法组合期间不要把未提交的拼音当成最终数据或触发破坏性动作。紧凑尺寸可顺序呈现编辑与预览，草稿持续保留。
- **如何验证**：输入未保存的中文姓名、电话和备注，中途展开/收拢/旋转；组合文本、选区和字段焦点不丢失。实时预览对应当前草稿；保存只提交一次，返回列表仍能找到该联系人。

## 4. Bulletin：阅读位置比版式稳定更重要

**已证实（Duo 已发布）**：Bulletin 3.1（2026-10-22）声明随开合和旋转调整布局与工具栏并保持阅读位置；展开可列表与文章并排，也可隐藏列表全屏阅读。版本说明还提到更窄的正文栏，以及调整尺寸、展开翻译、图片加载时的位置稳定性。[开发者提交的 App Store 介绍与版本记录](https://apps.apple.com/us/app/bulletin-rss-news-reader/id6476572500)

**迁移判断**：阅读连续性应围绕“文章 ID + 段落/语义锚点 + 段内偏移”，不能只保存旧布局的原始像素 scroll offset。展开后的更大宽度应服务于舒适行长或可选目录，不必把文字横拉到两侧。

- **适用**：RSS、书籍、文档、知识库、长篇聊天记录、说明书。
- **边界 / 反模式**：保留像素偏移却换了行宽，会落到另一段；为追求“像书”强制双页，可能令大字号正文无法阅读。双页要由可用宽度、字级和内容分页共同决定。
- **如何验证**：定位一句可辨认的正文，依次开合、旋转、调大字号、加载图片、显示翻译、隐藏列表；仍回到同一句附近，文章身份和选中文本保持。测试文章标题很长、图片失败和离线缓存时也没有空白跳顶。

## 5. Structured：姿态应改变使用方式

**已证实（Duo 已发布）**：Structured 4.6.5（2026-10-21）的版本说明明确包含开合自适应，以及为 book、tabletop 姿态设计的 Focus Timer。来源没有解释各姿态的完整控件位置，不能据此声称它一定采用某种上下分区。[开发者提交的 App Store 版本记录](https://apps.apple.com/us/app/structured-daily-planner-todo/id1499198946)

**迁移判断**：站在用户正在做的事上设计姿态：合拢便于随手查看与勾选，展开便于规划，桌面支起便于远一点看计时、近一点操作。只有任务确有变化时才建立专门模式。

- **适用**：专注计时、健身步骤、厨房流程、演讲排练、桌面状态看板。
- **边界 / 反模式**：不要为了展示铰链而让普通设置页也切成两块；不要开合一次就创建新计时器、重置计时或强制暂停。支持姿态不等于需要对每一度角度做不同布局。
- **如何验证**：启动一个带子任务的计时，在所有支持的姿态和前后台之间往返；到期时间、暂停状态、当前步骤保持正确。远距离确认剩余时间可辨，操作区域不在折痕处；VoiceOver 读取顺序和“暂停 / 继续”含义稳定。

## 6. Detail：让两个区域形成同一条创作反馈回路

**已证实（Duo 已发布）**：Detail 的 App Store 活动描述展开时视频和逐字稿并排，可点词跳转和执行剪辑。6.0.4（2026-10-12）版本说明描述内外屏对应的相机切换、外屏实时预览与提词、Book Mode 的外侧和后置双相机录制。[开发者提交的 App Store 活动与版本记录](https://apps.apple.com/us/app/detail-ai-video-editor/id1673518618)

**迁移判断**：创作场景优先组合“源材料 / 预览”和“精确编辑 / 控制”，并用同一选区、时间码或光标相互定位。外屏辅助内容面向另一个观看角色，不是把全部编辑界面镜像过去。

- **适用**：视频/音频剪辑、图像编辑、Markdown 预览、演示、录制与提词。
- **边界 / 反模式**：重新排版不能重新创建播放器/录制会话。外屏显示任何内容都应有明确用户操作与可见状态；不能因合拢就开始广播草稿、私密备注或自动开始录制。
- **如何验证**：选定逐字稿词语，改变姿态后视频时间码和选区仍一致；编辑、撤销与预览实时对应。录制中转姿态要验证会话结果和成品音画，而不只看屏幕；外屏关闭后辅助内容确实消失，并能从主界面辨认当前外屏状态。

## 7. Prime Video：桌面姿态把观看和补充信息分开

**已证实（Apple 官方发布案例）**：Apple 2026-10-22 介绍其半折时上部播放视频、下部显示 X-Ray 的演员与附加内容。此证据没有给出客户端版本号，也没有证明每种影片、系统和姿态均已验收。[Apple 官方案例：Enjoy Entertainment Anywhere](https://www.apple.com/newsroom/2026/10/developers-bring-incredible-new-app-experiences-to-iphone-duo/)

**迁移判断**：把“持续观看的内容”和“偶尔触达的控制 / 补充信息”放到合适的物理表面。对于纯媒体，保持正确比例与字幕可读比消灭视频周边的所有留边更重要；App 没铺满窗口和媒体按比例留边是不同问题。

- **适用**：视频、赛事、课程、视频会议与有伴随资料的直播。
- **边界 / 反模式**：补充信息不能争抢播放焦点；不要裁掉画面只为填满半屏，也不要把字幕压在折痕或控制层下。没有附加内容时，可以保留简洁控制，而不是制造一片“功能占位”。
- **如何验证**：播放到已知时间点，在平展、桌面半折、旋转和紧凑窗口之间往返；播放位置、清晰度设置、字幕和音轨选择保留。检查字幕、全屏退出和播放/暂停都能触达；下方详情滚动不会误拖视频时间线。

## 如何挑模式

| 用户当前任务 | 优先考虑 | 需要保留的连续性 | 不宜机械套用 |
| --- | --- | --- | --- |
| 找到并切换内容 | Things / Cardhop 的列表与详情 | 当前列表、对象、选择、返回路径 | 所有尺寸都强留侧栏 |
| 比较与规划 | Fantastical 的概览、可收起辅助栏与双窗口 | 日期、筛选、各窗口独立导航 | 把每个窗口做成同一个全局浏览状态 |
| 安静地读完 | Bulletin 的可隐藏列表与稳定正文 | 文章、语义阅读锚点、字级 | 横向拉长正文或强制双页 |
| 持续执行一步 | Structured 的姿态任务模式 | 截止时间、步骤、暂停状态 | 随角度反复重启整个流程 |
| 边改边看 | Detail / Cardhop 的输入结果回路 | 草稿、时间码、选区、撤销 | 两个看似相关但数据不同步的视图 |
| 支起后观看 | Prime Video 的内容与辅助区 | 播放器、字幕、音轨、会话 | 无条件上下平分，或者缩小触控区域 |

上表的优先顺序是本 skill 的设计判断。模式成功与否，要由当前 App 的实际任务、内容密度、可达性及转场验收决定；知名 App 采用过它不构成充分理由。

## 证据与时效边界

- 上述主案例均为 **iPhone Duo 的明确公开描述**，没有借 iPad 或 Android 的表现冒充 Duo 验证。原文说“iPad 式”时保留此措辞与适用边界。
- App Store 版本页会更新；重复研究时记录当时可见的版本、发布日期与具体行为。不要从“支持 Duo”一句话反推出未展示的全部姿态设计。
- **预告与发布分开**：Apple 2026-10-22 同一篇文章把 Word / Outlook 写作未来数周推出。未查到后续发布证据前，不能把它们记为已发布范本；同样不能把当时承诺下月更新的游戏当成当前可用的样板。[Apple 原文：Get More Done on the Go / Play on a Bigger Canvas](https://www.apple.com/newsroom/2026/10/developers-bring-incredible-new-app-experiences-to-iphone-duo/)
- 以上未提供某 App 在本机真机上支持所有姿态、通过无障碍验证或运行无故障的证据。真正交付 App 时，按状态矩阵采集自己的截图/录屏与功能结果。
